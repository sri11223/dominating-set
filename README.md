# Minimum dominating set

Find a minimum dominating set of an unlabelled graph: every vertex must be in the chosen set or adjacent to a chosen vertex, and the set must be no larger than the minimum possible. Minimum dominating set is NP-hard, so the whole difficulty is deciding which structure of a large instance allows the minimum to be reached.

## Difficulty

Development instances are small sparse graphs (up to 100 vertices, a few hundred edges) and include small representatives of both graph families - a relabelled 3-dimensional hypercube and a small hub/leaf graph - together with small graphs whose minima a maximum-gain greedy construction attains. The program must also find a minimum dominating set for each of four further instances drawn from the two families below.

* Two relabelled 15-dimensional hypercubes: 32768 vertices, 245760 edges, every vertex of degree 15. Vertex labels are arbitrary. Every vertex lies in exactly 16 closed neighbourhoods, so counting gives a lower bound of $32768/16 = 2048$, and the binary Hamming code of length 15 -- the perfect one-error-correcting code, the kernel of the parity-check matrix whose 15 columns are the non-zero vectors of $\mathbb F_2^4$ -- is a dominating set of exactly 2048 vertices. The minimum is therefore exactly 2048 and is provably attainable. A greedy or local-search construction reaches about 3486 vertices, and integer programming is far beyond the invocation budget at this size.
* Two hub/leaf instances (30000 vertices and 40000 edges each): 10000 hubs, each hub adjacent only to its own two private leaves, plus a sampled leaf layer in which one leaf of every hub carries no layer edge and the other carries a sampled 4-regular graph that never touches a hub. A hub's neighbours are exactly its two leaves, so the 10000 closed neighbourhoods {hub, leaf, leaf} are pairwise disjoint and cover every vertex; any dominating set contains at least one vertex from each of them, and the hubs attain that bound: the minima are exactly 10000 and are certified by this packing. The leaf layer is the family's separation gadget: it gives the layered leaf closed gain 6 against the hub's 3 (the unlayered leaf has gain 2) and realizes the standard maximum-gain greedy lower-bound construction for set cover and domination, so a maximum-gain greedy cover followed by redundancy pruning does not attain the certified bound (12163 vertices measured on the shipped instance against 10000) while the exact packing still certifies 10000. The family therefore separates the classical heuristic from the exact optimum on instances whose optimum is pinned by a two-sided certificate; that separation is the family's scientific purpose and the reason the leaf layer is sampled per instance. The solver must recover and certify the pairwise-disjoint packing for each 30000-vertex, 40000-edge hub/leaf graph with 10000 hubs, which a time-limited exact programme cannot do inside the invocation limit.

The two families carry two-sided certificates, so every claimed optimum is verifiable from the input alone: the cube optimum is pinned by the sphere-covering bound and the explicit perfect code, and the hub/leaf optimum by the packing lower bound and the hub set that attains it. Both are standard objects in extremal graph theory -- hypercube domination through the sphere-covering bound and perfect Hamming codes, and the disjoint-closed-neighbourhood packing bound -- and the task measures reconstructing that structure from arbitrary labels: coordinates and a perfect code for the cubes, and a disjoint covering family for the hub/leaf graphs. No heuristic cover reaches the cube optimum (greedy reaches about 3486 against 2048), so the exact-optimum gate is carried by the reconstruction rather than by the size of the graph alone.

## Reference solution

`solution/dominating_reference.py` keeps the maximum-gain greedy general path, exact branch and bound for small instances, redundancy elimination and local exchange. For large regular instances it rebuilds the cube coordinates level by level: a vertex in level $L+1$ is assigned the unique direction that keeps it adjacent to the $L$ required vertices of level $L$, checked with neighbour-set lookups; it then computes the sphere-covering bound $n/(d+1)$ and emits the Hamming code constructed from canonical parity-check columns $1 \ldots d$. For instances with a closed-size class whose closed neighbourhoods are pairwise disjoint and cover the vertex set it returns that family; it is a 2-packing, so the two bounds meet and the set is minimum.

## Independent producer

`tests/data/independent_certificate/producing_solver.py` is a third implementation written separately from the reference, and it shares no function bodies with it. It recovers the same optima along different routes:

* general instances by a lazily refreshed maximum-gain heap cover followed by redundancy pruning, and a fail-first set-cover search for small instances that branches on the uncovered vertex with the fewest covering closed neighbourhoods;
* relabelled hypercubes by verifying the BFS level-size statistics, recovering coordinates as the bitwise OR of the parent codes at the previous level, and building the perfect code as the kernel of a randomly column-permuted parity check on the non-zero vectors, meeting the sphere-covering bound;
* hub/leaf graphs by collecting a closed-size class and accepting it only when its closed neighbourhoods are pairwise disjoint and cover the graph.

Every emitted witness is re-checked by explicit domination, and the packaged public and heldout certificates were regenerated by this implementation and revalidated by the same grading code before shipping.

## Verification

Instances are deterministic synthetic constructions; no public benchmark instances are reused and construction truth is not read as the answer key.

The verifier checks strict JSON types, instance and edge roster validity, distinct in-range vertex indices, exact domination by closed neighbourhoods, and equality of the answer size with the independently certified minimum. The graded public set includes a relabelled cube and a small hub/leaf graph alongside development-scale graphs, so every development input shape also has a graded invocation. Every instance in a multi-instance answer is validated and all failures are collected into one message, so the logs name every instance that failed instead of only the first one; instances that pass are absent from the failure list. Malformed JSON, duplicate keys, CSV quoting, non-dominating answers, and size- or optimum-violating answers are covered by regression tests. Candidate answers are read link-proof: the grader `lstat`s the candidate path, rejects symbolic links and non-regular files outright, opens with `O_NOFOLLOW`, keeps the resolved path inside the expected output directory, and re-checks the opened descriptor before reading from it. The harness also screens each output directory and records any link or special entry as a violation before grading.

A derivation regression test builds two small hub-star instances as a deterministic function of the submitted solver's own bytes (fixed sizes 8 and 12 hubs, each certified by construction: the hubs dominate and their closed neighbourhoods are pairwise disjoint), runs the candidate through the same sandboxed invocation path (unprivileged user, network block, resource caps, fresh scratch, prior runtime tree wiped), and requires a valid minimum for each. The verifier-staged areas are swept between invocations, so memorised development or packaged answers cannot pass. The export also enforces the contract's single-file self-containment requirement: a sibling beside the solver source is removed at staging, the submission directory is left traverse-only and the staged source root-readable only, and `test_submission_is_self_contained` asserts that state.

## Budget

The agent has 18000 seconds (5 hours) to implement and debug a solver; the reference solves the large instances in a few seconds, so the per-invocation 3,600-second wall cutoff and the combined 14,400-second limit leave an enormous margin for slower legitimate methods. The 4,000,000-byte source cap is about four hundred times the packaged reference source, leaving ample headroom for conforming submissions.
